- Other findings:
  - Instrument bias against the reference (create-restricted-user): Tab from the Odoo name field lands in the login field, but the driver clicks it. The form also has an Alt+S save hotkey. Odoo's modelled human seconds (37.03) are therefore overstated by about 2 s, so a later 'win' on human seconds could be an artefact. The six driver paths were never checked as the shortest for each metric (probes/probe-odoo-paths.json).
  - switch-to-arabic is measured as lang.tester, who has only base.group_user. In this rig that user has no apps and lands on an empty client before and after the switch. The blind start and done screenshots show no Arabic text, and Odoo reloads an empty client, so machine seconds are understated (probes/probe-lang-tester-landing.json, screenshots 06 and 07). Use a user with a real working screen, such as Contacts.
  - There is no way to load the shared dataset (gauntlet/compare/data: contacts.csv, users.csv, rates.csv) into our product. `./erp up` seeds its own 100,000 users (for example abdullah.aldhaheri.10768@alnoor.example), not users.csv. The 'both products hold the same records' promise, and needle uniqueness, are enforced only on the Odoo side.
