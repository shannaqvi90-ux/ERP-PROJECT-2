Biggest gap
G2 checks only the client address, so a kernel permission rule that trusts the request's Host header passes every test

Round 13's loopback gap is fixed. G2ClientOriginTests now run every deny, grant and own-id matrix from 15 peer addresses. G2ClientAddressCodeTests reject any address read reachable from authorization. Inside the app container, a no-roles user calling from loopback gets 403. But the fix covers only the client address, not other parts of the request. Plant P13 makes the kernel's PermissionAuthorizationHandler pass any signed-in request whose Host is 'app', the compose service name. The plant's reasoning: internal callers (jobs, the report renderer, a proxy's upstream) address the app that way. All 146 G2/Rules/SelfTests tests, all G1 live tests and all 536 module and kernel tests passed with it in place. This is as realistic as P11. A default nginx 'proxy_pass http://app:8080;' rewrites Host to 'app:8080' on every browser request. The product also ships AllowedHosts '*', so any client can send 'Host: app' directly. One such rule would give every clerk of a UAE trading company the owner's rights over price lists, payroll and VAT, and no gate would notice. Fix it inside G2: (1) Widen the compiled-code gate so the authorization path may read nothing of the request except the session carriers and the endpoint's metadata. That means no Host, Scheme, Path, Query, Headers, Cookies or User-Agent, with each necessary read reviewed in a list, and not just the address APIs. (2) Run the deny-everything and grant-exactly-one matrices with varied Host values as well: the service name, localhost, 127.0.0.1, the container name, a configured public name and an unknown one.
