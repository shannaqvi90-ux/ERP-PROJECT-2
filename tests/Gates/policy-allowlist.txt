# Row-level security policies other than the standard tenant_isolation policy.
# Format: schema.table policy command roles  # reason   (command r = SELECT)
identity.users auth_resolver_read r erp_auth  # Lets identity.verify_sign_in() find accounts by e-mail before a tenant is known (sign-in). erp_auth is NOLOGIN; the app reaches it only through that function.
identity.user_credentials auth_resolver_read r erp_auth  # Lets identity.verify_sign_in() compare the stored hash with the app's proofs and read the salt. The application role itself cannot read password_hash (column privileges).
identity.sessions auth_resolver_read r erp_auth  # Lets identity.resolve_session() find a session by token hash before a tenant is known.
jobs.jobs due_tenants_read r erp_worker  # Lets the job worker (its own login role erp_worker, held only by the worker process; owns no table, no BYPASSRLS) name the workspaces with a job due or a lease run out (four columns: tenant_id, status, run_at, locked_until) before any workspace is bound. The web application cannot become this role.
jobs.schedules due_tenants_read r erp_worker  # The same for schedules (tenant_id, is_enabled, next_run_at): names a workspace with a schedule due, never a schedule.
audit.entries audit_trigger_insert a erp_auth  # Lets the audit trail's two trigger functions (audit.capture() and audit.custom_field_history(), SECURITY DEFINER, owned by the NOLOGIN erp_auth, the trail's only writers) write the audit row of the change that fired them, for the tenant of the changed row. The application role holds no INSERT on the trail at all; erp_auth cannot log in and the functions are trigger functions nobody can call.
