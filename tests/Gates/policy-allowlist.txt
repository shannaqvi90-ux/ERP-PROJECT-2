# Row-level security policies other than the standard tenant_isolation policy.
# Format: schema.table policy command roles  # reason   (command r = SELECT)
identity.users auth_resolver_read r erp_auth  # Lets identity.verify_sign_in() find accounts by e-mail before a tenant is known (sign-in). erp_auth is NOLOGIN; the app reaches it only through that function.
identity.user_credentials auth_resolver_read r erp_auth  # Lets identity.verify_sign_in() compare the stored hash with the app's proofs and read the salt. The application role itself cannot read password_hash (column privileges).
identity.sessions auth_resolver_read r erp_auth  # Lets identity.resolve_session() find a session by token hash before a tenant is known.
jobs.jobs due_tenants_read r erp_auth  # Lets jobs.due_tenants() name the workspaces with a job due or a lease run out (three columns: tenant_id, status, run_at, locked_until) before any workspace is bound. erp_auth is NOLOGIN; the app reaches it only through that function, which answers nothing inside a workspace and returns tenant ids only.
jobs.schedules due_tenants_read r erp_auth  # The same for schedules (tenant_id, is_enabled, next_run_at): names a workspace with a schedule due, never a schedule.
audit.entries audit_trigger_insert a erp_auth  # Lets audit.capture() (SECURITY DEFINER, owned by the NOLOGIN erp_auth, the audit trail's only writer) write the audit row of the change that fired it, for the tenant of the changed row, as the trigger did when it ran as the caller. The application role holds no INSERT on the trail at all; erp_auth cannot log in and the function is a trigger function nobody can call.
