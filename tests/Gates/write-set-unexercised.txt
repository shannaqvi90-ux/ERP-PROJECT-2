# Endpoints that change data which the write-set gate (tests/Erp.Gates.Tests/G2/WriteSets.cs)
# cannot get an accepted answer from, with the reason. The gate fails on an endpoint it cannot
# reach that is not listed here, and on a listed endpoint it reached or that does not exist.
# An endpoint the gate reaches at a fresh record but never at a record with dependents (critic p02
# round 14) is listed as METHOD /route/pattern [with dependents], with the reason.
# Format: METHOD /route/pattern  # reason
PUT /api/numbering/sequences/{id:guid}  # Every company holds a sequence for each document type from the moment it exists (seeded, or made with the company), so no POST makes one and this gate has no record to make for the edit; tests/Erp.Gates.Tests/G2/NumberingWriteSetTests.cs sends it as a user holding exactly numbering.sequences.update and judges its audited writes (the sequence's pattern columns and its own counters' next_value; nothing else).
PUT /api/currency/currencies/{id:guid}  # Every workspace holds the ISO 4217 currencies from its seed (no POST makes one), so this gate has no record to make for the edit; tests/Erp.Gates.Tests/G2/CurrencyWriteSetTests.cs sends it as a user holding exactly currency.currencies.update and judges its audited writes (is_active and max_rate_age_days of the one currency; nothing else).
POST /api/jobs/jobs/{id:guid}/rerun  # A job can be run again only once it has finished, and the gate's workspace runs no worker, so no job the generic gate queues ever finishes before it asks; tests/Erp.Gates.Tests/G2/JobsWriteSetTests.cs cancels a job (a cancelled job has finished), sends the request as a user holding exactly jobs.jobs.run and judges its audited writes (one new jobs.jobs row, nothing else), and checks that a reader and a user who may only cancel are refused with nothing written.
POST /api/attachments/contacts.contacts/{id:guid}/files  # An upload takes the file's bytes and its name in a header, not a JSON example the gate can build, and the bytes must be of the kind the name says; tests/Erp.Gates.Tests/G2/AttachmentsWriteSetTests.cs sends it as a user holding exactly contacts.contacts.update and judges its audited writes (one new attachments.files row with the file's name, kind, size, checksum and record; nothing else), and the other contacts permissions are refused with nothing written.
DELETE /api/attachments/contacts.contacts/{id:guid}/files/{fileId:guid}  # A delete needs a file that exists, and no POST the gate can send makes one (see the upload above); the same gate deletes the file it attached as a user holding exactly contacts.contacts.update and requires the removal of that one attachments.files row and nothing else.
