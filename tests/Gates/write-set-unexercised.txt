# Endpoints that change data which the write-set gate (tests/Erp.Gates.Tests/G2/WriteSets.cs)
# cannot get an accepted answer from, with the reason. The gate fails on an endpoint it cannot
# reach that is not listed here, and on a listed endpoint it reached or that does not exist.
# An endpoint the gate reaches at a fresh record but never at a record with dependents (critic p02
# round 14) is listed as METHOD /route/pattern [with dependents], with the reason.
# Format: METHOD /route/pattern  # reason
PUT /api/numbering/sequences/{id:guid}  # Every company holds a sequence for each document type from the moment it exists (seeded, or made with the company), so no POST makes one and this gate has no record to make for the edit; tests/Erp.Gates.Tests/G2/NumberingWriteSetTests.cs sends it as a user holding exactly numbering.sequences.update and judges its audited writes (the sequence's pattern columns and its own counters' next_value; nothing else).
PUT /api/currency/currencies/{id:guid}  # Every workspace holds the ISO 4217 currencies from its seed (no POST makes one), so this gate has no record to make for the edit; tests/Erp.Gates.Tests/G2/CurrencyWriteSetTests.cs sends it as a user holding exactly currency.currencies.update and judges its audited writes (is_active and max_rate_age_days of the one currency; nothing else).
POST /api/jobs/jobs/{id:guid}/rerun  # A job can be run again only once it has finished, and the gate's workspace runs no worker, so no job the generic gate queues ever finishes before it asks; tests/Erp.Gates.Tests/G2/JobsWriteSetTests.cs cancels a job (a cancelled job has finished), sends the request as a user holding exactly jobs.jobs.run and judges its audited writes (one new jobs.jobs row, nothing else), and checks that a reader and a user who may only cancel are refused with nothing written.
DELETE /api/attachments/contacts.contacts/files/{id:guid}  # A delete needs a file that exists, and the POST that attaches one is nested under the contact (/api/attachments/contacts.contacts/{id}/files), not a collection of the files the delete names; tests/Erp.Gates.Tests/G2/AttachmentsWriteSetTests.cs attaches a file, deletes it as a user holding exactly contacts.contacts.update and requires the removal of that one attachments.files row and nothing else.
POST /api/attachments/contacts.contacts/{id:guid}/files  # The generic gate names the record in {id} by a POST that creates it under the collection before the first parameter (/api/attachments/contacts.contacts), and the contact is made by another module's endpoint; tests/Erp.Gates.Tests/G2/AttachmentsWriteSetTests.cs sends it as a user holding exactly contacts.contacts.update and judges its audited writes (one new attachments.files row with the file's name, kind, size, checksum and contact; nothing else), and the other contacts permissions are refused with nothing written.
POST /api/importexport/contacts.contacts/imports/{id:guid}/run  # A run needs an uploaded file whose columns are mapped to a name; the generic gate sends an empty body to a file it did not upload, which is refused as an incomplete mapping. tests/Erp.Gates.Tests/G2/ImportExportWriteSetTests.cs uploads a file, runs a check and an import as a user holding exactly contacts.contacts.create and judges the audited writes (the check writes only the file's own record; the import adds the contacts of the file, nothing else), and refuses every other contacts permission with nothing written.
POST /api/importexport/tenant-exports/{id:guid}/download  # A download needs a finished export; the generic gate creates one through POST /api/importexport/tenant-exports, which the gate's own earlier start keeps running (one export at a time). tests/Erp.Gates.Tests/G2/ImportExportWriteSetTests.cs finishes an export and downloads it as a user holding exactly importexport.exports.download: the audit trail shows only the download count, moment and person on that export's record; the other export permissions are refused with nothing written.
