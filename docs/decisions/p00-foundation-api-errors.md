# p00 — API shape: OpenAPI from the running app, RFC 9457 problems, unit of work per request

Date: 2026-10-02. Piece: p00-foundation. Status: accepted.

## Decision

- The OpenAPI 3.1 document is generated by `Microsoft.AspNetCore.OpenApi` at
  `/api/openapi/v1.json`. Every operation carries `x-erp-permission` (or `x-erp-anonymous` with the
  reviewed reason), the session/bearer security schemes, and decimals as strings. A gate checks
  that every `/api` endpoint appears with a summary and its permission.
- Errors are RFC 9457 problem documents with a stable machine `code`, a `title` in the request's
  language (user preference, else `Accept-Language`), a `traceId` and, for validation, field errors
  `{field: [{code, message}]}`. Unknown `/api/*` paths answer a 404 problem instead of the SPA.
  Exceptions never leak internals: concurrency → 409, unique violation → 409, RLS violation or
  cross-tenant write → 404 (logged as an error), anything else → 500 with the trace id.
- One database transaction per request (`UnitOfWorkFilter`): committed only when the endpoint's
  result is a success status (nested `Results<…>` unions are unwrapped), rolled back otherwise.
- Optimistic concurrency on PostgreSQL `xmin`: updates send the `version` they read; a stale
  version answers 409.

## Why

- p15 (documented API for everything) builds on a document that is generated, not hand-written,
  so it cannot drift from the code.
